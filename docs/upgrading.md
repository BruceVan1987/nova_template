# 从 1.1.0 升级到 2.0.0

这次保留配置 schema 1，但改变了开写与交稿合同：新交付必须有完整逐幕计划，确认前必须有绑定当前版的两轮审阅记录。旧项目应按文件职责合并；bootstrap 只创建空项目。

## 合并顺序

1. 先保存当前 Git 状态，并备份未入库的 `.story-cache/reviews/`。在独立分支合并更新，保留可回退的升级前版本。
2. 更新框架工具与测试：`scripts/`、`tests/`、rollback 的工具脚本。若已有本地工具修改，逐项合并。
3. 合并工作流入口：`.cursor/skills/`、`.cursor/agents/`、`.cursor/rules/`、`.codex/agents/`；使用 Devin 时再合并 `.devin/`。保留个人平台配置与模型选择；共享 Skill 链接仍指向 `.cursor/skills/`。
4. 对照新模板合并 `AGENTS.md`、质量规范、控制卡模板和审阅协议。质量规则只在 `references/style-guide.md` 保存；保留作品专属语域、作者边界和已确定偏好。
5. 向配置补入缺少的 `lint` 字段并将 `template_version` 标为 `2.0.0`；保持 `mode: project`、原有预算、目标字数和体积阈值。两项新增声口检查默认关闭，按作者要求启用。
6. 缺少 `continuity/scene-log.md` 时创建空文件。逐章经过迁入按章号的段落，当前状态仍留事实源；迁移后核对时间、知情和物件位置，不按章号机械删除重要事实。
7. `references/voice-samples.md` 可暂时空着；需要默认声口时登记作者已确认正文的章号与起止锚句。锚句不是新的正文副本，改过源稿后重新核对。
8. 运行 `python3 scripts/doctor.py`。处理实际失败后再恢复写作；不要为通过检查伪造事实或审阅记录。

不要覆盖 `story.md`、人物、世界、剧情、时间线、连续性状态、已有章节和作者选定的样本。空模板里的占位内容只供新项目初始化。

## 旧章与进行中的草稿

已有确认状态不由升级自动改动，旧正稿也不批量重建。`plan`、`revise`、`review` 仍能读取旧控制卡；旧卡缺幕表时审阅报告该缺口，新开写或新交付前再补当前目标章计划。

旧审阅记录缺少新绑定字段时，不编辑指纹或完成标志来兼容；对要继续交付或重新确认的当前目标章重新运行两轮审阅。已有待处理问题应完整保留和处置。纯确认只能确认当前版，不能顺手改正文。

整体首读与语言轮需要没有目标章先验的独立会话。缺少隔离执行条件时如实报告缺口，不把自查记为独立审阅。

## 升级后的首次写章

在授权的目标章补好本章时间范围、完整逐幕安排与场面简报，运行 `plan-check`；用 `context --out` 保存当前 write 包，读完全部材料后再落笔。事实源或控制卡变更后刷新包，不能沿用旧输出。

样本为空的新项目不必等到已有章节才开始。配置样本却超过预算时，缩短锚点范围或增加 `context.voice_sample_chars`；必需事实材料超预算时调整事实分层或字符预算，不静默省略。
