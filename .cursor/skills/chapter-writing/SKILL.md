# 章节写作

本 Skill 只规定执行顺序。正文质量统一服从 [`references/style-guide.md`](../../../references/style-guide.md)，不得在此另建一套文风清单。

## 0. 章节正文严格串行

- 任何时刻只允许一个执行者生成或改写章节正文。禁止让多个 subagent、任务、线程或后台作业并行写不同章；也禁止并行生成同一章的任何完整、局部或候选正文，无论最后打算拼接还是只选一份。
- 连续写只推进作者授权的章数。第 N 章必须完成控制卡、正文、冷读、事实回写和校验，再从更新后的状态生成第 N+1 章上下文；维护日期、人物位置、物品、知识与权限的内部跨章表，授权末章交付后停止。
- 唯一并行例外是落笔前的“关键角色立场推演”。作者要求推演、关键人物围绕冲突／交易／关系发生多轮交锋，或已有声口混同问题时，自动为相关关键角色启用只读 subagent，不等作者逐人指定；其他多方选择确需独立核对时也可启用，普通过场不逐人派代理。启用前读取 [角色立场推演细则](references/character-stance.md)。
- 角色 subagent 不得写完整场景、完整对话回合或可直接拼接的正文段落。主执行者必须等全部角色推演返回，核对依据与知情边界后独自锁定控制卡并写正文；也可把整章正文交给第 3 节的唯一写手，自己在其返回前不碰正文。历史检索、章纲、正文、审阅、改稿和连续性回写仍全部串行。
- 主执行者在串行期间独占正文与连续性事实源的编辑权。若发现另一个章节写作任务已在运行，不再启动新的正文生成；先停止重叠任务，核对已产生文件和当前状态，再从唯一串行入口继续。

## 1. 取得最小上下文

```bash
python3 scripts/story.py context --task plan --chapter <章号> --out .story-cache/context/plan-<章号>.md
```

- 按[上下文完整读取协议](../../../references/context-reading.md)分段读完 `plan` 文件，确定人物与线索；生成回执不等于读过，工具返回被截断时补读缺段。完成第 2 节的角色推演与控制卡后，才进入第 3 节生成供落笔使用的 `write` 包；其中只载入唯一质量规范的“开写视图”，用来确定声口、关系和场景发动，不提前载入冷读禁线。
- `write` 包末尾依次是上章结尾原文、控制卡、[默认声口样本](../../../references/voice-samples.md)和唯一规范的「落笔前自检」。模仿声口样本的叙述密度和对白来回，不模仿包内台账的写法；「落笔前自检」是落笔前最后读的一段，承接本书已确定的声口要求。主执行者自己落笔或改稿时同样最后读它。未配置样本的新项目可直接开写；已有锚点失效时先修锚点。
- 上下文命令默认使用 `novel-project.json` 的字符预算；只在额外定向材料确需扩容时指定 `--max-chars`。时间线、当前状态、实际出场人物和正文任务质量规范是 P0 必需材料，预算不足会报错；检查纳入与省略清单后再落笔，缺项先修上下文脚本，不用记忆补。
- 新章包必须包含 `plot/timeline.md` 的时间线与消息排程、`continuity/state.md` 的当前状态和关键知情范围、上章结尾原文、直接承接人物热档；`plan` 包载入当前 arc，锁卡后的 `write` 包用目标控制卡承接单元方向。
- 信件、口信、案卷和远程生活汇报中的写信人、被具体描写者也算事实依赖人物；若被预算省略，用一个或多个 `--focus <人物>` 重新生成。
- 两名复现人物会有三轮以上对白、私信或关系动作时，包内必须有目标章适用的 `P0 关系声口卡`。长期关系缺卡时先补 `continuity/relationships.md`；一次性关系不强建。
- 承接伏笔或悬念时，按台账章号定向回读首次出现原文及必要前后段，列内部清单：`线索 → 原始章节 → 本章仅提及／推进／回收`。找不到原文，不把推测写成事实。
- 近期正文已经声口漂移，或多人关系戏容易写成公事对白时，可从作者已经认可的正文中选一章真正接近目标滋味的已确认章节，用 `--voice-chapter <章号>` 重新生成 `plan`／`write` 包。一次只选一章，样章只约束 HOW，不提供目标章事实。
- 只在明确缺口时用 `--focus` 或 `--include`；禁止通读全书。跨元日时按人物年龄锚点统一更新存活人物，旧章年龄仍按旧时点计算。

## 2. 锁定章节控制卡

- 从当前 arc 读取所属单元卡，按 [`AGENTS.md`](../../../AGENTS.md#草稿与确认边界) 确定授权与停止位置。明确写章且单元方向已锁定时，自行完成控制卡并继续正文；先看控制卡的请求在提交后停止。缺少单元方向时先回到 `plot-structure` 与作者确定，不靠单章控制卡临时拼出路线。
- 控制卡使用 [`references/chapter-template.md`](../../../references/chapter-template.md)，包含场面简报、本章时间范围和逐幕安排。把讨论中选定的幕表写进这一份卡；静态知情名单仍以状态文件为准，不在卡中追加禁用清单。
- 控制卡用完整白话和全名写，先写「场面简报」：谁想要什么、双方当下的状态、谁会先作出选择、停在哪个画面。它离正文最近，写成台账缩写，正文就会跟着缩写。`lint` 会拦下单字简称；缺简报时 `lint` 对 draft 提醒，`ready-chapter` 交付时直接拒绝，新章与改稿都一样。
- 按唯一规范的[场内的信息与决定](../../../references/style-guide.md#场内的信息与决定)区分已定先后与暂拟表现。作者明确锁定的事实与方向保留，具体问法、动作和反制表现由人物现场选择推导；若现场展开使已定信息入口或先后关系不能成立，先修计划，不把后幕的结果提前借来维持原路径。
- 按第 0 节需要角色推演时，先等全部推演返回，再按细则收拢人物选择，把选定的本场表达倾向融入「场面简报」，据此锁定控制卡。
- 发动部件缺失时停止开写，回到章纲并章、压缩或更换入口。控制卡的答案只用于组织动作，正文不得逐项证明计划已经被遵守。
- 只有程序、说明、赶路或既知结果复核而无不可逆变化的内容，优先并入相邻章，不靠新增误会或人物撑篇幅。
- 检查最近两章主要发动机；连续两章已经同构时，第三章必须换入口、主场动作和焦点欲望。切换外部 POV 或更换全书默认发动机时，控制卡须记录作者对本章的明确授权。

## 3. 创建并写作

```bash
python3 scripts/story.py new-chapter <卷号> <标题>
```

1. 将锁定的控制卡填入 `chapters/drafts/` 的目标章文件；不手工编号，不碰 `chapters/final/`。随后检查计划结构，再生成并完整读取 `write` 包，不能沿用锁卡前的旧包；自己落笔和委派唯一写手都遵守这一步：

   ```bash
   python3 scripts/story.py plan-check <章号>
   python3 scripts/story.py context --task write --chapter <章号> --out .story-cache/context/write-<章号>.md
   ```

   - 结构检查只核对字段和表格是否完整，不证明因果正确。读完当前包后确认各幕原文完整出现在控制卡块里，才开始正文；缺幕、空表或包与锁定卡不一致时先修交接。
   - 可选的干净写手：主执行者锁定控制卡后，可把正文交给项目代理 [`chapter-drafter`](../../agents/chapter-drafter.md) 作为本章唯一正文执行者，只给它 `write` 包路径和目标章文件；主执行者等待其返回，期间不写、不改任何正文，也不另派第二个写手。返回后由主执行者继续交稿检查与事实回写。这仍是单一执行者串行写作，只是让落笔的上下文里没有规划与审计材料。
2. 同一写手按幕顺序串行展开。每幕落笔前以幕初状态和上一幕实际写出的结果为入口，核对焦点人物、手边物件及本幕关键触发；写完后对照幕末状态，发现人物提前使用后续信息或实际结果改变了下一幕前提，就修到承接闭合再继续。执行与质量判断按唯一规范的“对话与人物关系”和[场内的信息与决定](../../../references/style-guide.md#场内的信息与决定)，不逐句填表，不把核对过程写进正文，也不在幕间重新请求已有授权。
3. 私密频道与公开场景切换时，用现场动作自然标出声音是否外放；不在开写阶段逐项做受众验收。
4. 角色调度表是候选入口，不是待办清单。每章最多引入一名需要长期记忆的具名角色；新长期人物先用 `character-management` 建最小档案，再 `--focus` 后写。
5. 关系、秘密、保护或高风险位置优先给新同伴时，核对长期亲属、师徒和稳定助手是否会注意；差别合理也要有正文条件或反应。
6. 正文依赖真实资料且读者确需知道时，章末最多放三条简短资料注；原创设定不加资料注。

## 4. 交稿前检查

正文完成后，先按 [`references/chapter-review-workflow.md`](../../../references/chapter-review-workflow.md) 完成隔离的整体首读，再生成事实核对包：

```bash
python3 scripts/story.py context --task review --chapter <章号> --out .story-cache/context/review-<章号>.md
```

此包用于连续性核对，不发给整体首读者。按交稿协议完成其余检查与受众审计，随后按第 5 节回写事实，最后回到该协议的“交稿与确认”收口；检查命令、复读条件与汇报要求均由该协议定义。

## 5. 回写事实

- 填好 frontmatter 的人物、地点、物品、提及、摘要、状态变化和伏笔字段。
- 人物／物品／秘密变化同步 `continuity/state.md`；伏笔与悬念同步各自 `_index.md`；术语同步 `glossary`；方位同步 `worldbuilding/geography.md`。这些文件只改写成最新状态，不追加“第N章实际……”段落。
- 本章的旁听者、钱物执行账、走位和控制卡落实情况写进 [`continuity/scene-log.md`](../../../continuity/scene-log.md) 的 `## NNNN` 段；改稿与审阅会按章号自动取用，开写不载入。`lint` 会拦下事实源里的逐章记录。
- 新人物首次有效行动，或旧人物的行动、关系、权限、认知变化时，更新人物档案与 `plot/character-pipeline.md`。单纯在场不算推进。
- 关系阶段、公开／私下语域、亲密许可或稳定冲突方式改变时，在 `continuity/relationships.md` 关闭旧区间、新增阶段；纯措辞增温不改事实卡。
