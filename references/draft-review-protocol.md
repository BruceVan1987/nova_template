# 草稿审阅共享协议

## 边界

- 只审 `chapters/drafts/` 中 `draft` 或 `待审核` 章节；始终只读。
- 已确认章节交 `revision-continuity`；绝不运行 `confirm-chapter` 或编辑正稿、status、台账。
- 禁止通读全书。先读纯正文，再按需要生成事实核对包、定向回读源文件；旧伏笔要回看首次出现原文，后续未确认章不得倒灌为事实。

## 流程

1. 已收到经导出且不含作者信息的正文快照时直接读取；否则运行 `python3 scripts/story.py review-text N`。先完整读取纯正文与 [`style-guide.md`](style-guide.md)，不打开含控制卡的草稿源文件、上下文包、人物档案、摘要或后续计划。导出失败则报告格式问题，不手工猜分隔符后继续。
2. 按唯一规范独立做整体首读。**先当读者回答五问，写在报告最前面，每问引原句：** 哪里最想往下翻；哪里出戏；谁的行为说不通（他知道什么、想要什么、为什么不那样做）；哪里读着想跳过；哪里在解释读者自己推得出来的东西（心理、推理、交代、复述上文）。第二到第四问有任何一条成立，就记为“必须改”，结论至少是“需较大修改”；第五问逐句列出，记为“必须改”，处置是删。这一条压过规范里的逐项检查。五问答完，再按规范补查。`story.md` 写有「平台与读者节奏」时，整体首读可以读取 `story.md`：它是作品级合同，相当于读者点开前看到的定位，不含目标章先验。逐章判断异常、核心设定的亮相节点和设定讲解的篇幅是否守住合同，未守住按“建议改”报告；在合同规定的开篇章节内越过硬节点的，按“必须改”报告。先定位使场面改向的关键选择，用前后原句核对“对话与人物关系”中的策略变化，再下整体结论；不能用情节梗概或“讨价—反制—供述”的顺序代替判断。报告保留最有影响的依据，不要求凑问题或逐句填表。需要前文核对的内容单列，不用猜测的作者意图替正文补因果。若委派为 `blind-only`，在此返回并停止，不做后续事实读取；这是交稿整体轮的独立部分，不代表整章已完成连续性和语言核验。
   若委派为 `language-only`，不做整体判断，也不读事实包、控制卡或其他章节；读完规范后按作品当前唯一规范逐句检查正文，逐条列出原句、类别和改句，统计各类条数后返回。没有命中的类别写“无”。这是交稿语言轮的独立部分。
3. 完整审阅先输出首读判断，再运行 `python3 scripts/story.py context --task review --chapter N --out .story-cache/context/review-N.md`，使用项目默认字符预算，按[上下文完整读取协议](context-reading.md)读完整个文件，再按纳入清单核对事实。按唯一规范的[场内的信息与决定](style-guide.md#场内的信息与决定)，沿实际正文逐幕核对入口和出口，回指关键反应的前置信息，再对照控制卡幕表与时间线和消息排程。旧卡缺幕表时直接报告这项缺口，不能用章末摘要补成幕初已知。只有明确缺口才用 `--focus` 或 `--include` 补入；规范已经读过，不重复评读包内同一副本。连续性证据可纠正误报，但控制卡完成度不能覆盖首次读感问题。随后再单独完整读一遍正文，仅判断词句和声口，逐句对照作品当前声口要求，不同时核对台账。
4. 最后运行 `python3 scripts/story.py lint` 和 `python3 scripts/audience_audit.py <目标章>`，只报告目标章相关结果，并按实际受众判断命中。零命中不代表信件、口信和公开文本自动安全。注意现有上下文／lint 可能刷新派生缓存，只读指不编辑正文、事实源、记录或状态；`blind-only` 不调用它们。
5. 没有明显问题直接通过，不为填栏目制造意见。始终不运行会写记录或状态的 `review-start`、`review-finish`、`ready-chapter`。误读作者信息时须明示，不能称为独立盲读。

## 分级

- 必须改：读者五问里的出戏、行为说不通、读着想跳过、解释读者自己推得出来的东西；连续性、人设、限知、物品、知情、物理、因果硬伤及必须靠猜才能读懂之处。
- 建议改：生涩、审讯腔、讲义、纯流程、段尾讲题，以及明显影响连读的问题，默认应改。按作品已定基调判断冲突与表达，不把单一作品的强度或口语偏好升级为通用要求。
- 可选打磨：真正不影响理解与连读的洁癖项。

## 输出

```markdown
# 草稿审阅：第N章《标题》（status）
## 读者五问
## 结论
## 必须改（阻塞定稿）
## 建议改（读感与质量；默认应改）
## 可选打磨（可有可无）
## 一致性备忘（供主 agent 回写）
## lint 相关
```

每条意见写明位置、问题、原因和修改方向；没有则写“无”。结论用“可定稿／小改后可定稿／需较大修改”。
