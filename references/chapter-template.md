# 单章文件模板

本模板对应**草稿**文件，路径格式：`chapters/drafts/<卷文件夹>/<四位章号>-<标题>.md`，例如 `chapters/drafts/卷一/0001-初入云都.md`。用 `python3 scripts/story.py new-chapter <卷号> <标题>` 自动生成，不要手写文件名/路径。

草稿是唯一的元数据来源。等这一章被用户确认后，运行 `python3 scripts/story.py confirm-chapter <章号>` 会自动去掉下面的 frontmatter 和"本章控制卡"区块，把干净正文写到 `chapters/final/<卷文件夹>/` 下——那份正稿文件不需要、也不应该手工维护。

```markdown
---
schema-version: 1
chapter: 1
volume: 1
title: ""
pov: ""                  # 本章视角人物
status: draft            # draft（初稿）/ 待审核（写完等确认）/ 已确认（已用 confirm-chapter 生成正稿）
word-count: 0            # 由 scripts/story.py wordcount --write 自动填
characters: []           # 本章出场人物（姓名，需已在 characters/ 登记）
locations: []            # 本章涉及地点
objects: []              # 本章发生状态变化（换手/换地点）的关键物品名，需同步更新 continuity/state.md 的"最后更新章节"
mentions: []             # 本章仅"被提及"（非实际出场）的人物，用于合法区分"已死角色被追忆"与"复活穿帮"
summary: ""              # 一到两句话摘要，供后续章节写作时快速读取上下文，不读全文
state-changes: []        # 本章造成的状态变化，写完后同步回 continuity/state.md，例如："某角色 获得 某物品"
promises-planted: []     # 本章新埋下的伏笔，需同步登记进 continuity/promises/_index.md
promises-paid: []        # 本章回收的伏笔
---

## 本章控制卡

- 场面简报：三到五句完整白话，像讲给一个没看过台账的人听：这场戏谁想要什么、各自处在什么状态、谁会先作出选择、最后停在哪个画面。只写处境和发生了什么，不写“因为……所以……”，也不替人物说出他为什么这样做：原因由写手落笔前自己盘出来，写进写作包的推理会被原样誊进正文。写作包里它离正文最近，决定落笔的语气
- 人物画面：本章第一次出场或久未出场的人物，每人一两句：外貌锚点（脸、身段、衣着或一个习惯动作，可带评价词，后面跟一个具体细节撑住）加一个性格点或毛病（如记仇、爱看热闹、嘴硬心软）；再次出场的人物只写用来认出他的那个特征。按唯一质量规范第 2 节“人物画面”
- 已定目标：作者确认的本章／单元变化；与下列可调整的场景路径分开
- 物件与动作：冲突落在哪件看得见、拿得动的东西或行为上；物件若承担转折枢纽，注明其来历已在前文何处建立
- 施压与阻力：谁或什么阻止人物得到想要的结果；阻力如何改变选择。关系章里谁的愿望卡住了谁
- 选择与代价（暂拟路径）：关键参与者被逼到哪一步才改换策略，具体损失什么；按唯一质量规范随现场因果调整
- 落点：人物以为什么已经解决；生活、声誉或关系实际留下了什么不可逆事实
- 本章时间范围：本章开始与结束的故事日期或相对时段；同一场持续展开时可写同一时段，不为填表编造精确时辰

### 逐幕安排

| 幕次 | 时段与地点 | 幕初状态 | 本幕依次发生的事 | 知情变化与触发点 | 幕末状态 |
|---|---|---|---|---|---|
| 1 |  |  |  |  |  |

控制卡分两层。**写作层**进写作包：场面简报、人物画面、物件与动作、本章时间范围，以及逐幕表的「时段与地点」「本幕依次发生的事」。**核对层**只进规划与审阅包：已定目标、施压与阻力、选择与代价、落点，以及逐幕表的「幕初状态」「知情变化与触发点」「幕末状态」，用来锁定计划和事后查因果、限知，写手看不到。

打斗、赌局、几方对撞这类大场面，规划会话另写**规划推理链**，存 `plot/logic/<四位章号>.md`，不写进控制卡：每方一条，用箭头连起来（要什么 → 看见什么 → 做什么），不写成句子。它只进 plan 与 review 包，写手读不到；写手落笔前从处境自己盘一份，规划会话拿两份对照（见 chapter-writing 第 3 节）。

控制卡要短：写作层合计不超过目标单章字数的 25%，逐幕表每格不超过 120 字，`plan-check` 会拦下超长的卡。「本幕依次发生的事」只写谁作出什么选择、局面因此怎样变，不写动作细节、台词和知情边界；核对层各栏也写成一两句结论，不复述场面。

按场景或局势转折分幕，简单章可以只有一幕。幕初只写本场关键人物已经面对的事实、已知或误信；本幕事件按发生顺序写，知情变化标明谁在何处通过什么动作或话轮得到什么，不把幕末结果放回幕初。没有新增知情时照实写“无新增知情”，不为凑表编消息。幕末记录将交给下一幕的有效变化。各格用完整白话，具体问法、动作和停顿仍留给正文展开。

逐幕安排与场面简报同属这一份控制卡，按唯一规范的[场内的信息与决定](style-guide.md#场内的信息与决定)组织；开写前用 `python3 scripts/story.py plan-check N` 校验结构，再生成写作包。静态知情名单仍以状态文件为准，不重复抄全表；写后实际经过留在[现场记录](../continuity/scene-log.md)。
```
