# 上下文包的生成与完整读取

本页只规定文件交接与读取方式，不增加正文质量规则。规划、开写、改稿和事实核对都使用 `context --out .story-cache/context/<任务>-<章号>.md` 保存当前包；`--out` 的简短回执只表示文件已生成，不表示执行者已经读过材料。

1. 生成成功后，从文件头按顺序读取整包。根据文件字符数或行数分段，每段控制在工具返回上限内；遇到 `truncated`、省略号替代正文或未返回的末段，缩小读取范围，补读缺段后再继续。不能把终端打印过、纳入清单中出现过、路径已经交给写手，当成内容已被读取。
2. 对照包头的纳入与省略清单核对必需材料。开写必须在控制卡块中看到锁定的本章时间范围及全部幕表原文；改过卡或事实源后重新生成受影响的包，不能沿用旧文件。
3. `write` 包最后仍按上章结尾、控制卡、声口样本、落笔前自检的顺序读取。委派唯一写手时交付这个文件的路径，由写手完成同样的分段读取；只读首读者仍只接收纯正文，不接收本包。

文件较长时，可用下列命令按字符取段。后续调用把起点移到上一段实际返回的终点，直到读到总字符数；单段仍被截断就缩小段长。命令不会编辑文件。

```bash
python3 - .story-cache/context/plan-N.md 0 6000 <<'PY'
from pathlib import Path
import sys
text = Path(sys.argv[1]).read_text(encoding="utf-8")
start, size = int(sys.argv[2]), int(sys.argv[3])
end = min(start + size, len(text))
print(f"字符区间 [{start}, {end}) / {len(text)}")
print(text[start:end], end="")
PY
```

字符预算决定脚本能装入多少材料，工具返回上限决定一次能读到多少内容，两者分别核对。结构检查与完整读取都不能代替正文的时序和因果判断。
