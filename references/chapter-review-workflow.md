# 章节交稿检查流程

这是写章、改稿及作者确认时补充核验的执行协议，不是第二份文风规范。质量判断只引用 [`style-guide.md`](style-guide.md)。两轮冷读串行完成：整体轮由未参与构思或修改的只读审阅者先读正文，主执行者随后核对事实；语言轮也先交给另一个没读过本章上下文包的只读审阅者逐句检查，主执行者随后处置。记录与改稿仍由唯一主执行者完成。只读审阅使用 [草稿审阅协议](draft-review-protocol.md)，不写记录、不改状态。

## 两轮冷读

局部改稿、错别字与标点修正也执行两轮冷读。主执行者先建立当前正文快照：

```bash
python3 scripts/story.py review-start N --stage overall
```

命令输出完整读者正文（含章末资料注），不附控制卡、摘要或台账。将该快照与唯一质量规范交给一个无历史继承、未参与构思或修改的只读审阅者，使用共享协议的 `blind-only` 模式。创建子代理时必须使用无历史继承的会话；委派提示只给章号、草稿状态、`review-start` 返回的精确快照路径和审阅模式。快照是审阅者的第一个章节读取入口；审阅者不得再查索引、打开草稿源文件或自行导出另一份正文。不提供控制卡、章节摘要、角色推演或声口便笺、台账、后续安排、作者预期、已诊断问题或理想结论。无历史继承仍不够：若运行时摘要、记忆提示或环境注入已经泄露目标章摘要、关键转折、修改意见或预期结论，审阅者必须判定本轮污染并停止，主执行者改用没有目标章先验的临时隔离会话；被污染的报告不得写成盲读证据。审阅者必须读到末尾，独立给出基于原句的整体判断；关键对话的声口判断按规范第 2 节引用具体话轮说明。主执行者等待其返回，不同时改正文、写下一章或派第二人产出候选正文。

整体首读完成前，审阅者不得读取 `context --task review`，也不得打开含控制卡的草稿源文件。若误读，标明污染，不将结果冒充盲读；另找未接触答案的审阅者。没有独立执行条件时可以继续自查，但报告独立首读尚缺，不把同一作者自读记成已完成的独立审阅。

随后主执行者使用所用 skill 的完整 `review` 或 `revise` 文件包核对事实，按[上下文完整读取协议](context-reading.md)读完整个文件；本轮已经完整读取且相关内容未变的包不重复加载。按唯一规范的[场内的信息与决定](style-guide.md#场内的信息与决定)，沿实际正文逐幕核对入口、事件先后和出口，将关键反应回指到此前的信息入口或决定原句，再与控制卡幕表、时间线和消息排程核对；特别检查本幕后段或下一幕才出现的信息是否提前进入了对白或判断。判断与处置仍记在本轮 `notes`／`findings`，不另加审核轮次或字段。首次判断不能因计划已经写明而被冲淡；确有前文证据可纠正误报，不能用作者私有答案补足读者看不见的动机。需要修订时在已有授权内修改正文，不为通过流程追加解释句；纯确认补检发现正文或标题问题则报告后停止，不自行改稿或改题。

做过角色推演的本章，由主执行者在首读后对照推演与场面简报，核对选定的表达差异实际留下了什么、是否在转写时被抹平；结合正文话轮把判断写入现有 `notes`，发现问题仍用 `findings` 处置，不增加审核轮次或字段。推演只用于追查差异丢失在哪里，不能代替正文证据，也不补发给独立首读者让其按预期重新判断；改动正文仍按下文执行版本失效与复读。

局部改稿的整体轮重点复核修改段前后三段及关联段，不能只保证选中的一句单独成立；语言轮仍完整读当前正文。

整体轮完成前，按唯一规范中的[章节标题](style-guide.md#章节标题)核对当前题名，并连读相邻章节标题；在本轮读记中结合正文原句，说明题名让人期待什么、读后增加什么意味。规划暂名在此落实；若更换标题，依下文的版本失效流程重新绑定冷读记录，不为换题改动正文。

记录实际判断，完成这轮后再进入语言冷读：

```bash
python3 scripts/story.py review-finish N --stage overall
python3 scripts/story.py review-start N --stage language
```

语言轮同样先隔离。把 `review-start --stage language` 打印的快照路径交给一个新开的、无历史继承且没读过本章任何上下文包的只读审阅者，使用共享协议的 `language-only` 模式，只提供章号、草稿状态、快照的精确路径和审阅模式。该快照同样是它唯一的章节读取入口；不查索引、草稿源文件、控制卡、摘要、context 包或其他章节。运行时摘要、记忆提示或环境注入若已经泄露目标章内容，本轮同样作废并更换临时隔离会话。审阅者按作品当前唯一规范逐句检查，返回原句、类别和改句。主执行者读过大量台账，对缩写和台账句不敏感，不能用自己的复读代替这一步。

审阅者返回后，主执行者重新连续读当前正文，只处理词句和声口，不同时核对台账。逐条处置审阅意见：改掉的记 `fixed`；确属文书引用、人物固定声口或语境需要的记 `retained` 并写理由。发现新的事实或因果问题，回到整体轮处理，不带着问题继续交稿。没有独立执行条件时可以自查，但在读记里写明独立语言轮尚缺。

```bash
python3 scripts/story.py review-finish N --stage language
```

## 记录怎么填

命令给出 `.story-cache/reviews/NNNN/record.json` 的实际路径。仅用文件编辑工具填写当前轮的 `notes` 和顶层 `findings`；其他字段、版本指纹、快照和历史由程序维护。每轮至少留一条引用当前原句的判断依据；它可以解释保留的理由，不要求制造问题，也不代表只检查这一句。

整体轮读记须注明独立审阅者标识、所读快照以及输入是否隔离，并保留其关键选择判断与主执行者的处置依据；不能只摘录赞同部分，也不能因审阅者说“通过”而跳过作者已指出或主执行者仍能举证的问题。记录验证只验证文本、版本与字段，不证明审阅者独立或理由正确。

当前轮 `notes` 的条目格式：

```json
{"quote": "当前正文中的完整原句", "reason": "结合本句语境说明判断，不只写通过或已读"}
```

无问题时 `findings` 保持空列表。发现问题时追加条目，不删除旧问题；`source_sha256` 从发现问题时那一轮的 `prose_sha256` 复制，程序会到原始快照核对原句：

```json
{
  "stage": "language",
  "source_sha256": "发现问题时的正文指纹",
  "quote": "原始快照中的问题句",
  "problem": "具体问题",
  "decision": "open",
  "replacement": "",
  "reason": ""
}
```

修订后将 `decision` 改为 `fixed`，填写当前正文中的 `replacement` 和修改理由；删除时 `replacement` 留空。决定保留则用 `retained`，写明语境理由，原句应仍在正文中。原句及改句应取足够的前后文以定位问题；脚本只能核验文本存在，不能判断理由是否正确。

## 受众审计

两轮冷读完成后，对目标章运行：

```bash
python3 scripts/audience_audit.py <目标章路径>
```

逐项把命中行标为旁白、内心、私密频道、公开台词或可经手文本，写明实际受众。零命中不等于通过，仍检查未收录关键词的信件、口信、公开对白、题字与案卷；“对方听不懂”不是保密理由。若发现需改正文的问题，按下文返回复读流程。

## 修改后的复读与版本失效

- 在冷读、受众审计或后续校验中动了正文，当前轮记录会过期，不能直接 `review-finish`。修订完成后重新从 `overall` 开始，至少复读改动段前后三段及关联段、确认整体判断仍适用，再完整进行语言轮和受众审计；不要复制旧读记冒充复读。
- 重开只重置步骤，不清空已发现的问题，并保留旧步骤及原始快照。改句再次调整时，更新该问题的处置证据。
- 标题、读者正文、资料注或质量规范改变会使记录失效；字数、摘要、控制卡和状态字段的改动不使正文指纹失效。事实源改变仍须按原 skill 做受影响检查，指纹不代替知情与连续性判断。
- 完成后再改读记或问题处置，也须复核并重新 `review-finish`。不得手改指纹或完成标记迁就正文版本。

## 交稿与确认

新章与未确认改稿完成上述检查后，按调用 skill 回写事实，再运行：

```bash
python3 scripts/story.py wordcount --write
python3 scripts/story.py ready-chapter N
```

`ready-chapter` 已包含两轮记录核验和 `lint`，检查记录是否齐全、对应当前正文和规范、问题是否已处置及原句证据是否存在。项目启用了 `lint.light_register` 时，还核验自定词频阈值及语言轮保留证据；新模板默认关闭该作品偏好。全部成功才置为 `待审核`，失败不改状态。同一版本不紧邻重复运行 `review-check` 或 `lint`；检查后又有相关改动，须按上文重新核验。不得手改状态绕过交稿入口。

已确认旧章修订后，按调用 skill 回写变化的事实；字数变化时运行 `wordcount --write`，再运行 `lint`，按作者授权用 `confirm-chapter N` 刷新正稿，不用 `ready-chapter` 降级。纯确认由 `story-maintenance` 核验当前版本，必要时完成本协议的补检后直接确认，不走未确认改稿的事实回写与待审核收口。

只有作者明确确认才运行 `confirm-chapter N`；该命令也检查当前版冷读记录，记录就绪不构成作者授权。`review-check` 保留用于独立查看记录就绪情况、判断确认前是否需补检等场景。

记录不进入故事事实源或开写上下文，不在章节正文中添加验收说明。它们是本地过程产物，不入 Git；删除或换机器后缺记录就重新检查，不自动视为通过。已有章节不会被追溯改状态，也不补造历史检查；下一次交稿或确认时使用新入口。

程序不能证明执行者认真读过全文、不能阻止伪造理由，也不能证明正文好读。交稿简短说明正文变化和最不放心之处，具体格式服从作者要求。不用记录核验结果自评质量。
