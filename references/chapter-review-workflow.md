# 章节交稿检查流程

这是执行协议，不是第二份文风规范。质量判断只引用 [`style-guide.md`](style-guide.md)。写作、改稿均由当前执行者串行完成；只读审阅不写记录、不改状态。

## 两轮冷读

先按所用 skill 完整读取 `review` 或 `revise` 上下文包，然后执行：

```bash
python3 scripts/story.py review-start N --stage overall
```

命令输出完整读者正文（含章末资料注），不附控制卡、摘要或台账。必须完整读取输出；若工具截断，继续读取命令给出的快照文件至末尾。先脱离控制卡连续冷读，再按唯一规范核对人物、因果、知情、连续性和叙事价值。需要修订时先改正文，不为通过流程追加解释句。

记录实际判断，完成这轮后再进入语言冷读：

```bash
python3 scripts/story.py review-finish N --stage overall
python3 scripts/story.py review-start N --stage language
```

语言轮重新连续读当前正文，只处理词句和声口，不同时核对台账。应用唯一规范中的基本声口、对话与高频痕迹要求；对疑似问题比较原句与自然完整的表达，依据具体语境决定修改或保留。若发现新的事实或因果问题，回到整体轮处理，不带着问题继续交稿。

```bash
python3 scripts/story.py review-finish N --stage language
```

## 记录怎么填

命令给出 `.story-cache/reviews/NNNN/record.json` 的实际路径。仅用文件编辑工具填写当前轮的 `notes` 和顶层 `findings`；其他字段、版本指纹、快照和历史由程序维护。每轮至少留一条引用当前原句的判断依据；它可以解释保留的理由，不要求制造问题，也不代表只检查这一句。

当前轮 `notes` 的条目格式：

```json
{"quote": "当前正文中的完整原句", "reason": "结合本句语境说明判断，不只写通过或已读"}
```

无问题时 `findings` 保持空列表。发现问题时追加条目，不删除旧问题；`source_sha256` 从发现问题时那一轮的 `prose_sha256` 复制，程序会到原始快照核对原句：

```json
{
  "stage": "language",
  "source_sha256": "发现问题时的正文指纹",
  "quote": "原始快照中的问题句",
  "problem": "具体问题",
  "decision": "open",
  "replacement": "",
  "reason": ""
}
```

修订后将 `decision` 改为 `fixed`，填写当前正文中的 `replacement` 和修改理由；删除时 `replacement` 留空。决定保留则用 `retained`，写明语境理由，原句应仍在正文中。原句及改句应取足够的前后文以定位问题；脚本只能核验文本存在，不能判断理由是否正确。

## 修改后的复读与版本失效

- 在冷读中动了正文，当前轮记录会过期，不能直接 `review-finish`。修订完成后重新从 `overall` 开始，至少复读改动及关联段、确认整体判断仍适用，再完整进行语言轮；不要复制旧读记冒充复读。
- 重开只重置步骤，不清空已发现的问题，并保留旧步骤及原始快照。改句再次调整时，更新该问题的处置证据。
- 标题、读者正文、资料注或质量规范改变会使记录失效；字数、摘要、控制卡和状态字段的改动不使正文指纹失效。事实源改变仍须按原 skill 做受影响检查，指纹不代替知情与连续性判断。
- 完成后再改读记或问题处置，也须复核并重新 `review-finish`。不得手改指纹或完成标记迁就正文版本。

## 交稿与确认

依原 skill 完成受众审计、事实回写和字数更新后：

```bash
python3 scripts/story.py review-check N
python3 scripts/story.py ready-chapter N
```

`review-check` 只核验两轮记录是否齐全、对应当前正文和规范、问题是否已处置及原句证据是否存在。`ready-chapter` 再运行既有 `lint`，全部成功才置为 `待审核`；失败不改状态。不得手改状态绕过交稿入口。

只有作者明确确认才运行 `confirm-chapter N`；该命令也检查当前版冷读记录，但记录就绪不构成作者授权。已确认旧章修订后用 `review-check` 检查，按作者授权重新确认，不用 `ready-chapter` 降级。

记录不进入故事事实源或开写上下文，不在章节正文中添加验收说明。它们是本地过程产物，不入 Git；删除或换机器后缺记录就重新检查，不自动视为通过。已有章节不会被追溯改状态，也不补造历史检查；下一次交稿或确认时使用新入口。

程序不能证明执行者认真读过全文、不能阻止伪造理由，也不能证明正文好读。交稿仍按项目要求简短说明正文变化和不放心之处，不用记录核验结果自评质量。
